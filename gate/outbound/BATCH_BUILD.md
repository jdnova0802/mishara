# Batch build

Standing rule for every future batch, in every vertical. This does not rewrite the Oct 21 Spark batch.

The hunt already forces one source and one object before a vertical is written up. The same order applies after the vertical is chosen. A batch is not N letters that later get a source attached. A batch is one public document that already covers N names, and letters only for the names that document actually has a row for.

## Order

1. The vertical is already chosen.
2. Before any company on the target list gets a body, find one public, citable dataset that covers the list. A court-docket search across the batch, an AM Best table, a regulatory filing set, a Federal Register notice that names several of them, NAIC filings, or whatever fits that vertical.
3. Pull each recipient’s own row out of that dataset.
4. Write the body from what is in that row. The sentence does not exist first.
5. A name on the list with no row does not get a body. It goes back to research. Same result as `SEND_GATE.md`, reached while the batch is being built.

`SEND_GATE.md` still stops a letter that has no dated, named, public source. It is the exit check. It is not permission to draft a category sentence and then go looking for something to attach.

## Worked order

Concert was built this way. One public dataset, the ALIRT/Vesttoo collateral table, standing on NAIC statutory filings, covers many companies at once. The body comes from the row already there for that recipient.

Copy-first is the failure. Pick the vertical, write a sentence that is true of the category, swap in the company name. Bourret’s letter is what that order produces. Finding a source afterward, one recipient at a time, to justify a sentence already written, is the same order with an extra step.
