## Glossary (every word you need)

Plain definitions. If two terms look similar, the difference is spelled out.

### The primitive (core three words)

| Term | Meaning |
|------|---------|
| **Primitive** | The smallest complete idea Gate is built on — three words below. |
| **may** | Single-use **permission that counts** as authorization to do an irreversible act. Not a chat message. Not a policy paragraph. Consumed once. |
| **sheath** | The **binding / fail-closed wrapper** around may: it can’t quietly reopen, soft-live, or be waved through by vibe. Controls and contains the permission. |
| **prove** | **Stranger-verifiable evidence** that a may was issued/redeemed (typically a public receipt URL). No private login required to check the fact of clearance. |
| **may · sheath · prove** | Spoken as “may, sheath, prove” — the full Gate mouth in one phrase. |
| **Redeem / redeem** | The act of **consuming** the may at the irreversible moment (the commit). Speech is not redeem. |
| **Consume-once / single-use** | After redeem, that may is spent; you cannot reuse the same ticket. |
| **Throat** | Metaphor for the **core permission power** (the mouth of authorization). “Don’t sell the throat” = don’t sell may / critical clearance control. |
| **Mouth** | Metaphor for Gate as the **authorization opening** where irreversible writes must pass. |
| **Rail** | The clearance pathway others rent — like a payment rail, but for permission finality. |
| **Grammar** | Shared rules of what counts as valid may / sheath / prove across partners. |

### Velaru fuse states

| Term | Meaning |
|------|---------|
| **Fuse / fuse engine** | State machine that says whether authorization is live, armed, dead, or unsigned. |
| **LIVE** | Authorization is active; irreversible action is allowed under that ticket. |
| **ARMED** | Ready / staged; not yet the final live commit (or armed for a controlled transition — context-specific). |
| **DEAD** | Authorization is terminated; silence or loss must not revive it into LIVE. |
| **UNSIGNED** | No valid sealed authorization present. |
| **Silence ≠ LIVE** | If the link drops or nobody answers, that must **not** count as approval. |
| **Fail-closed** | On error/uncertainty, default to **block**, not allow. |
| **Soft-yes / soft-LIVE** | Looks like approval (chat, vibe, dashboard green) but is **not** a consumed may. Forbidden as a substitute for redeem. |

### Acts & reality

| Term | Meaning |
|------|---------|
| **Irreversible act** | Something that cannot honestly be undone: bind a policy, release funds, trip a load, hand off crisis routing, etc. |
| **Speech** | Words, plans, model output, “I will transfer” — **not** the act. |
| **Action / act** | The world-changing commit; in Gate, typically the **redeem**. |
| **Authorization** | Permission that is real under Gate grammar (may redeemed), not merely requested. |
| **Commit / commit edge** | The exact moment the irreversible write happens. |
| **Epoch** | A bounded time window for may; when it ends, permission does not silently continue. |
| **Epoch HALT** | Hard stop of an epoch — may cannot soft-resurrect after halt. |
| **Edition / edition pin** | Lock *which version* of a form/policy/model was live at bind (kills “which wording did we sell?” fog). |
| **Mandate** | Named human/org authority an agent or officer is allowed to act under. |
| **Agent / agentic** | Software that can initiate tool calls or payments; needs may before irreversible release. |
| **Illocution** | (Philosophy) Doing something *by* saying/redeeming under rules — Gate’s “counts as may.” Optional depth; see triad crawl. |
| **Status function / counts as** | (Philosophy) “X counts as Y in context C” — e.g. this redeem counts as authorized bind. |
