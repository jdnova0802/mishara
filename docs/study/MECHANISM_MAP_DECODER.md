# MECHANISM MAP DECODER — PLAIN ENGLISH

Methodology. Decoder lock for a **plain-English mechanism map**. Not a syllabus. Not Nisaba. Not How to Learn. Not tailored to one subject.

How to Learn fills a **cycle row** (who / does what / to whom / under what authority / date). This decoder audits a **mechanism map**: has the note earned trust as study material, or does it only look finished?

**In genre:** AI / Technical Map, Political Economy Map, Perception / Control Map, and other Maps/Branches notes in that house style (what it is, what it is not, how a case runs, how it fails, companions, OPEN, falsifier). In-repo example: `docs/study/PERCEPTION_CONTROL_MAP.md`.

**Out of genre — do not run this file on them:**

- 11-field claims grids (Religion as Institution, Socionomics, atlases, class/trade/war lookup maps). Those already have their own audit logic.
- Cycle docs. Use How to Learn.
- Curriculum Do-lists (`HOME_LEARNABLE_CURRICULUM.md`, `PHASE3_PERCEPTION_CONTROL.md`). Those are hours and artifacts, not maps.
- Ops (The Morning, X lineup, standing priority list).

Pull date **24 Nov 2026**, America/New_York. Re-run when the map is edited or when a live case hits it. Do not schedule this as Deep hours.

Heading aliases (same cell, different titles):

| Cell | Common titles |
|------|----------------|
| Case run | How a Case Runs · How it actually works · How it actually fails (failures are part of the run) |
| Boundary | What This Is NOT · What this is not |
| Starters | Best Free Starters · named live URLs in the map itself |
| Open | OPEN · Open problems |
| Split | Do not mash · model vs system · mechanism vs wrapper |

If a required cell has no heading and no equivalent paragraph, that cell is empty. Empty is a fail, not a style choice.

A map is a thing that can be **run**. Fill the six. If you cannot, you do not have study material yet — you have a brochure.

---

1. **Spoken-recall** — close the doc. Say the case-run out loud: the steps, in order, including how it fails. No peeking, no “I know it when I see it.”

   Pass: you can walk one full case (predict → update → decision, or quote → bind → claim, or encapsulate → handshake → fail-closed) and name the failure that looks like success.

   Fail: you remember slogans, product names, or the table of companions, but not the run.

   If 1 fails: **unread**. The doc has been looked at. It has not been studied.

2. **Boundary stress** — pick one **real adjacent** case (a live weld, a neighboring Deep, a vendor demo, a news item). Hold it against What This Is NOT.

   Pass: the boundary **kills** the mash. The adjacent case is named as not-this, and you can say why in one sentence.

   Fail: the boundary is mood (“not hype,” “not everything”) or the adjacent case slides back in under a synonym (SITL as flight, Palantir as Kalman, a model card as the deployed system, a quote as a bind).

   If 2 fails: **mash**. The map is a mood board.

3. **Resource currency** — every Best Free Starters link (or named starter URL in the map). HTTP 200 or a **named** redirect. As-of date on the map. Depth: a starter a practitioner can run this week, not a 400-page handbook dumped to look complete, not a blog that was superseded by the spec.

   Pass: links live, dated, right altitude.

   Fail: 404/403 with no named redirect; “see Wikipedia”; a 2019 tutorial still listed after the field moved; curriculum URLs pasted in as if they were the map.

   If 3 fails: **stale bibliography**. Do not study from it until the list is re-hit.

4. **Open-problems staleness** — OPEN is a claim about **now**. Check the field since the pull date.

   Pass: still-open items stay; resolved items are removed or marked closed with a date; a new public open that a practitioner would hit is present or explicitly refused.

   Fail: a solved problem still listed as open; a brochure gap listed as if it were a research problem; OPEN used as a junk drawer.

   If 4 fails: **museum**. The map is a snapshot of when it was written.

5. **Mechanism vs marketing** — split what the **underlying mechanism** can do from what a **system/wrapper** built on it claims.

   Template case (AI / Technical Map): the model is not the product. Prompt injection against a model ≠ the agent’s tool loop ≠ the vendor’s “safe by default” page.

   Perception template: KF/EKF/UKF math ≠ PX4 ≠ “the drone.” A covariance is not doctrine.

   Pass: one breath can name mechanism, wrapper, and the claim the wrapper makes that the mechanism does not guarantee.

   Fail: the map treats a brand, a ROS screenshot, a model name, or a policy PDF as the machine.

   If 5 fails: **wrapper**. You have marketing with equations nearby.

6. **Depth calibration** — specialist / practitioner. A person who has to **use** the machine could act from this. A person who only collects vocabulary could not fake it for long.

   Pass: machines are unmashed (EKF is not UKF; quote is not bind); failure modes are operational; no unverified name-drop; no TED-talk compression that deletes the failure.

   Fail: pop explainer (“AI is just math”) **or** costume jargon (terms used once, never run).

   If 6 fails: **pop** or **costume**. Neither is PhD-adjacent depth. Neither is Director mouth.

---

If 1 fails: unread.  
If 1 passes and 2 fails: clean mash (worse — you can recite the wrong boundary).  
If 1–2 pass and 3–4 fail: you studied a **dead** map.  
If 1–4 pass and 5 fails: you studied a **product**.  
If 1–5 pass and 6 fails: you studied a **poster**.

A mechanism map still owes, or it is not house style:

- A falsifier (which cell dies if you are wrong).
- Companion split (this map vs the Do-list vs the adjacent Director note). Do not paste curriculum milestones into the map.
- Pull date (America/New_York).

One case-run from memory + one adjacent case that the boundary actually holds + one live starter + one still-open problem + one mechanism/wrapper split. Not a collection of finished-looking headings.
